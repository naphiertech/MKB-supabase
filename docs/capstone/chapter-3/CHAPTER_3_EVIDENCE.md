# Chapter III Evidence Ledger

## Purpose and audit boundary

This internal document records the repository evidence used to prepare Chapter III, *Design and Methodology*. It is not part of the submitted research paper. The audit was performed against the `main` branch at commit `b378a5f` (`Add hub attendance geofence support`) on August 31, 2026. The current repository, forward-only migrations, generated database types, service code, tests, and verified project documentation were treated as the technical source of truth. Repository evidence confirms tracked implementation, not deployment to a particular live Supabase project.

The audit did not modify application code, database migrations, generated types, or runtime configuration. The root `attenrider_schema.sql` was not used because the current maintenance documentation identifies the migration history under `dashboard/supabase/migrations/` as authoritative for an existing environment.

## Inconsistencies and caution notes

1. **Agile is confirmed by the researchers, not reconstructed from repository chronology:** the chapter may name Agile and relate its stages to current implementation, but it must not invent sprint dates, sprint counts, ceremonies, meetings, stakeholder sessions, or undocumented historical events.
2. **Hub attendance-geofence enforcement is incomplete:** the August 31 migration and Admin UI configure hub coordinates/radius, while Time In currently checks fresh GPS but not distance from the hub. UI copy implying active physical attendance enforcement is ahead of implementation.
3. **Operational zone geofence does not block Time In:** out-of-zone behavior is monitored and can create a violation after an attendance session begins.
4. **Biometric terminology is inconsistent:** product/title/UI copy uses “Face Recognition” and “Facial Recognition,” whereas the implemented attendance decision is one-to-one face verification. `dashboard/README.md` also incorrectly summarizes MediaPipe as face matching; MediaPipe is used for blink liveness, while face-api.js performs descriptor matching.
5. **OpenCV is legacy/absent:** no current OpenCV runtime exists. TensorFlow.js is present indirectly through face-api.js, not as a direct application dependency.
6. **FMS import is technically substantial but hidden:** page, services, migration, and tests exist, but sidebar links are commented out. It should not be presented as a generally available user workflow without qualification.
7. **Generated database types lag the newest FMS tables:** `dashboard/src/types/supabase.ts` includes the August 31 hub geofence columns but does not list `external_rider_mappings`, `fms_import_batches`, or `fms_daily_rider_observations`, despite the current migration and source using them.
8. **Legacy payroll enum values remain:** `processed` and `flagged` are still in `payroll_status`, but current authoritative workflow transitions use Draft, Pending, Approved, Rejected, and Paid.
9. **No payslip table exists:** payslips are generated client-side from protected payroll records and immutable delivery/adjustment snapshots.
10. **No raw attendance selfie is stored in `attendance_logs`:** the rider profile can retain a face image and descriptor, but attendance verification frames, liveness scores, and confidence values are not persisted with each log.
11. **Verification evidence differs by layer:** the current Vitest suite passed locally; pgTAP, browser smoke tests, live Supabase behavior, and deployment were not verified in this audit.
12. **Next.js build configuration ignores framework build-time TypeScript errors:** CI separately runs `pnpm run typecheck`, so the paper should describe separate type checking rather than imply `next build` alone guarantees it.
13. **Landing marketing copy is not implementation authority:** public copy such as “MediaPipe 3D Liveness Detection” must not be expanded into accuracy, depth-sensor, or certified anti-spoofing claims.
14. **Current root typecheck fails:** the failure is confined to a Hub-service test mock response shape at `dashboard/src/services/hubs/hubService.test.ts:207`; dashboard lint reports no errors and 45 warnings. These pre-existing verification results are not represented as a completed fix.
